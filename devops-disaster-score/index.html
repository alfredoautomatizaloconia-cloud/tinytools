How the score is calculated

    
The Disaster Score (0–100) is calculated from public GitHub API data. Higher = more likely to break prod. We weigh five factors: days since last commit (50 pts max), open issue volume relative to project size (20 pts max), absence of a README (10 pts), absence of a license file (10 pts), and whether the repo appears abandoned (archival status, zero recent watchers). Same repo always produces the same score — deterministic, no AI hallucinations.

    
A score of 0–20 means your repo is suspiciously well-maintained. 21–40 is solid with some rough edges. 41–60 means technical debt is accruing. 61–80 means you're shipping into chaos. 81–100 means your on-call rotation deserves combat pay.

    
Why "disaster" specifically?

    
The framing is intentional. "Code quality" tools get ignored because they're abstract. "Disaster" gets people's attention because production outages have feelings attached to them. We're not measuring code quality — we're measuring production blast radius.

    
Share your score

    
The deep link encodes the repo path, so anyone clicking your link sees the same repo scored the same way. Drop the badge in your README to prove your repo is (or isn't) a disaster. Bet your coworker their repo is worse than yours.

    
What score is "good"?

    
Most popular open-source repos score 10–30. Actively maintained projects with responsive issue queues hit 5–15. Hobby projects that haven't been touched since 2021 reliably hit 70+. Enterprise repos internal tools score 55–75 which is why your on-call alerts go off at 3am.
