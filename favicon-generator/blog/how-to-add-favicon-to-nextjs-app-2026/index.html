How to Add a Favicon to a Next.js App in 2026 — The Complete Guide

Published May 9, 2026 · 9 min read · Tagged: nextjs, favicon, app-router, metadata-api

Adding a favicon to a Next.js app should take five minutes. Yet a remarkable number of production sites ship in 2026 with a 404 on /favicon.ico, a stale icon Chrome refuses to forget, or a 14-file zip from a 2017 favicon generator that nobody actually needs anymore.

This guide walks through what works in modern Next.js — App Router conventions, the metadata API, dark-mode SVG, the manifest.webmanifest, and the cache-busting trick that saves an afternoon of frustration. By the end you'll have a minimal five-file set that covers 99% of real traffic, plus the exact code to copy.

The two ways Next.js handles favicons

Next.js (App Router, 13+) gives you two paths. Both work; they trade convenience for control.

1. File-based conventions (the magic path)

Drop a file with a known name into app/ and Next.js automatically generates the right <link> tags at build time. The recognized names:

  • favicon.ico — the legacy fallback, served at /favicon.ico
  • icon.svg (or .png) — the modern icon
  • apple-icon.png — for iOS home-screen and Safari pinned tabs
  • opengraph-image.png, twitter-image.png — for social cards

Put them in app/ (the root segment) and they apply globally. Put them in app/blog/ and they apply only to /blog/* routes — useful for sub-brands.

2. The metadata API (the explicit path)

If you want to control sizes, types, and dark-mode media queries explicitly, export a metadata object from your root layout:

// app/layout.tsx
export const metadata = {
  icons: {
    icon: [
      { url: '/icon.svg', type: 'image/svg+xml' },
      { url: '/icon-192.png', sizes: '192x192', type: 'image/png' },
    ],
    apple: '/apple-icon.png',
    other: [
      { rel: 'mask-icon', url: '/safari-pinned.svg', color: '#f59e0b' },
    ],
  },
};

Use the metadata API when the file conventions can't express what you need — multiple icon sizes, custom rel values, or dark-mode swaps. Otherwise lean on conventions; less code is less to break.

Step-by-step: adding the favicon to a fresh Next.js app

Step 1 — Place the files

With App Router (Next.js 13+), put the files in app/:

app/
  ├── layout.tsx
  ├── page.tsx
  ├── favicon.ico
  ├── icon.svg
  ├── apple-icon.png
  └── opengraph-image.png

If you're still on Pages Router, put them in public/ instead and reference them manually in _document.tsx. The conventions only fire under app/.

Step 2 — Wire the manifest

For PWA install prompts and Android home-screen icons, you need a manifest. The cleanest approach is app/manifest.ts:

// app/manifest.ts
import type { MetadataRoute } from 'next';

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: 'My App',
    short_name: 'MyApp',
    description: 'A description for the install prompt.',
    start_url: '/',
    display: 'standalone',
    background_color: '#0a0a0f',
    theme_color: '#f59e0b',
    icons: [
      { src: '/icon-192.png', sizes: '192x192', type: 'image/png' },
      { src: '/icon-512.png', sizes: '512x512', type: 'image/png' },
      { src: '/icon-512-maskable.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
    ],
  };
}

Next.js serves this at /manifest.webmanifest with the right MIME type. The maskable icon is the one with safe padding — Android crops aggressively, and a non-maskable icon will get its edges chopped off on Pixel devices.

Step 3 — Dark-mode SVG (optional but cheap)

Browsers honor prefers-color-scheme inside an SVG favicon. Add a <style> block:

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <style>
    path { fill: #1a1a1a; }
    @media (prefers-color-scheme: dark) {
      path { fill: #fafafa; }
    }
  </style>
  <path d="..."/>
</svg>

Now the browser tab icon is dark-on-light during the day and light-on-dark at night. No JavaScript, no extra requests.

Step 4 — Verify the build

Run next build, then inspect the rendered HTML in .next/server/app/index.html (or the network tab). You should see something like:

<link rel="icon" href="/icon.svg?xyz" type="image/svg+xml"/>
<link rel="apple-touch-icon" href="/apple-icon.png?abc"/>
<link rel="manifest" href="/manifest.webmanifest"/>

The query strings (?xyz) are Next.js cache-busting hashes — they change whenever the source file changes, which solves the single most annoying favicon problem in existence.

Debugging: "I updated the favicon but Chrome won't show it"

This is the favicon problem everyone hits eventually. Five things to try, in order:

  1. Hard reload won't fix it. Favicons are cached separately from the page. Hard-reloading / does nothing.
  2. Open /favicon.ico directly in a new tab and hard-reload that URL. This is the usual fix.
  3. Check DevTools → Application → Manifest → Icons. If the icon URL there is wrong, your manifest.webmanifest is the culprit, not the file.
  4. Append a dummy query string in your link tag (?v=2). Useful for testing only — remove it after.
  5. Try an incognito window. If it works there, you have a stale cache, not a bug.

If incognito also shows the wrong icon, the file you uploaded is genuinely wrong — open the deployed URL of /icon.svg directly and look at it.

Common pitfalls

Putting files in public/ with App Router. Files in public/ still serve, but Next.js won't auto-generate the <link> tags. You get a working favicon at the root URL but nothing in the HTML — which means social previews and AI scrapers miss it.

Conflicting favicon.ico in public/ and app/. If both exist, app/favicon.ico wins, but the public/ one still serves at /favicon.ico. Pick one.

Forgetting the maskable icon. Android adds a circular crop. Without a maskable icon, your logo gets a haircut on every Pixel. Add a 512×512 with ~10% padding and label it purpose: 'maskable' in the manifest.

SVG without viewBox. SVG favicons need a viewBox attribute. Without it, the icon renders at literal pixel sizes and clips weirdly in some browsers.

What about Pages Router?

If you're on pages/ instead of app/, the file conventions don't fire. Put the icons in public/ and reference them in _document.tsx:

// pages/_document.tsx
<Head>
  <link rel="icon" type="image/svg+xml" href="/icon.svg"/>
  <link rel="icon" type="image/x-icon" href="/favicon.ico"/>
  <link rel="apple-touch-icon" href="/apple-icon.png"/>
  <link rel="manifest" href="/manifest.webmanifest"/>
</Head>

It works fine. But if you're starting a new project in 2026, default to App Router — the conventions are genuinely less code.

The five-minute checklist

  1. Generate the five files (SVG, ICO, apple-icon, 192, 512).
  2. Drop them into app/ with the right names.
  3. Add app/manifest.ts with both 192 and 512 icons (one maskable).
  4. Run next build and verify the rendered HTML has the link tags.
  5. Test in an incognito window after deploy. If it shows the right icon there, you're done.
